# Editorial Workflow

## Required sequence

1. Select content purpose and intended reader.
2. Read the relevant knowledge files.
3. Check the Fact Register.
4. Prepare an article brief.
5. Identify evidence required.
6. Gather and register sources.
7. Gather founder, product-team, or Tea Lab input.
8. Draft in British English.
9. Run a factual audit.
10. Run duplication and readability audits.
11. Run legal and claims review.
12. Obtain human approval.
13. Publish only from an approved state.
14. Validate metadata, schema, sitemap, and links.
15. Monitor factual accuracy, user usefulness, and performance.
16. Review and update only when justified; do not change the updated date for cosmetic edits.

## Publication states

| State | Meaning |
|---|---|
| DRAFT | Work in progress; not approved for publication |
| FACT CHECK REQUIRED | One or more factual statements lack verification |
| FOUNDER REVIEW REQUIRED | Founder input or approval is necessary |
| EXPERT REVIEW REQUIRED | Qualified subject review is necessary |
| LEGAL REVIEW REQUIRED | Legal or regulatory review is necessary |
| APPROVED | All required reviewers approved the exact version |
| PUBLISHED | Approved version is live and technically validated |
| ARCHIVED | Withdrawn from active publication but retained in version history |

An item can require multiple review states simultaneously. Record approvals against a version identifier or commit so later edits do not inherit approval automatically.
